# 剧本交付、来源与转换进度

本模块产生文本剧本和审阅对照，不登记角色实际末态、视频段号、分镜提交或视频交付时长。来源、版本与常规进度内部保存，不向用户重复展示。规则由技能包独立说明；作品资料只取当次可读取的正文、当前采用前稿、必要承接信息与用户决定，不依赖旧聊天记忆、特定本机目录或私有记录，也不要求完整历史聊天。

## 单份可编辑对照稿

1. **交付物只有一份**：交付一份可编辑 HTML，左栏“原版”只读，右栏“改后版本”可直接编辑。整页右侧统一滚动，两栏同步滚动。页面顶部提供“复制全部改后版本”，各节标题行右侧提供“复制本节”，均以右栏当前编辑内容为准。撤销、重做、保存及其他共同界面要求按[统一交付](../../short-drama-storyboard/references/delivery.md)【可编辑 HTML 交付】执行。
2. **表内只有两边正文**：列名为“原版”“改后版本”。左栏逐字保留对应原文，含原标点、引号和段落；右栏放按模块规则改编的完整剧本，含必要场景、动作、表演和声音。按有意义的叙事单元对齐，覆盖本次全部原文及完整改编稿，未改部分也保留；左栏完整不等于右栏逐句重述，右栏可按核心边界补充、改动和删减。不用摘要、短锚点或“同上”代替全文，不在正文插入删改说明。
3. **正文自然换行与用途区分**：使用正常段落与换行，不把原始 HTML 换行标记写给用户。剧情所需场景标题、动作、声音正文及真实入画文字的用途可辨；不另加交付前言、改编解释区、第三列、来源号、来源映射或常规进度。原文本身已有内容在左栏保持，不为格式清洁删原文。
4. **表达落实后交审阅**：按 [expression-selection.md](expression-selection.md) 写清具体视听内容、场景人物、动作与道具关系、叙事层次、声音主体和实际内容及先后范围。可以跨段清楚对应，不强制统一段落模板，也不新增镜头设计。必要信息与声画双向自然时长匹配须落实，不能靠表格完整掩盖表达未完成。
5. **待定与授权**：正常改编完成但待审，不等于存在表达缺口。文本错误、真正缺项和续接冲突按表达参考【真实缺口与解除】处理；未获相关自主授权时，说明具体问题、推荐方案和影响并询问，受影响部分保留草稿。在明确授权内能依据现有资料解决的直接完成，不重复请示；无法在核心边界内解决或缺少必要资料时仍如实说明。
6. **【本次审核与自主决断】**：表达改编、文本纠错、状态适配、审阅定稿与旧分镜返工是不同权限。状态适配先执行expression-selection.md【情境变化与状态适配】，常规改编自由不免除此要求。正常表达改编默认可自主安排，不自动免除文本纠错的说明与询问，也不代表当前稿已定稿或允许返工旧分镜。用户明确让助手自行决定相关事项或将相关全流程交由助手自主处理时，在其范围内执行，不例行等待逐步审批；仍守住故事核心、可读取事实和明确保留要求。经统一入口执行时，按[总入口](../../short-drama-storyboard/SKILL.md)【全流程自主委托】承接本次覆盖文本处理与自主定稿的授权，仅指定阶段顺序不等于全部决定授权。授权范围、对象及持续性按用户明示记录，不把“有时会全权交给助手”当作本次已经全权，也不把一次授权当作无限授权。没有相应免审或自主定稿授权时，默认交付后请用户审阅；仅在用户明确采用相应稿本与范围后才登记采用，详见【版本承接】。用户选择逐项指定时，一次只问一个独立事项，答后再问下一项。已明确的下一步保存并执行，不反复追问。

## 内部来源与进度

- 原文接收时赋稳定来源号与版本，绑定实际消息或附件及本次范围；转换稿另有稿号、版本和审阅状态。不得将原文及其转换稿当作两份新正文。同一已确认来源的续接沿用类型，新的或替换正文重新确认。
- 每个转换单元关联来源段落、必要字符范围与正文承载位置，区分原文明示事实、常规补充与改写、删减、用户资料及具体修订决定。核心信息、声音用途与重要改动可追溯；不要求所有原词和非必要细节在右栏逐项复现，内部记录也不能代替正文中的必要表达。
- 按表达参考【前后剧本的连续承接】取得并使用当前采用前稿及必要资料，不只核对名称一致。保存承接所需状态、实际断点与用户决定，缺少必要前稿时具体说明并索取，不凭记忆补齐，也不要求完整历史聊天。
- 保存已处理范围、表达落实范围、真实待定、下一未处理位置、未完成单元、当前采用稿本及用户决定，区分普通待审与真实缺口。完整交付、可追溯且必要表达落实的单元才记为转换完成；采用与定稿状态另行登记。中断从实际未完成处恢复，不重做已完成的无关单元。
- 原文技术要求的原文、范围及性质内部保留，不交下游执行人工作业；其中承担核心理解或后续情节的必要信息在正文落实，原文摄影指示按作用保留。
- 不展示内部来源映射、来源 JSON 或常规进度文件。需要解释实际问题时，只引用足以定位的原句与影响，不把内部编号和整套记录塞进用户成品。

## 手动编辑、修订与定稿

- **版本承接**：用户可以手动编辑，也可以委托助手修改。用户明确采用当前稿或明确指定以某份修改稿为准时，按其明示范围采用对应版本，不重复确认。提问、讨论、提修改意见或仅表示看过不构成采用；只认可局部不等于整稿定稿。已授权自主定稿时，在授权范围内直接完成。采用稿必须实际可读取；缺少最新版时只索取该稿，不拿旧稿替代。沉默、时间经过或未检测到编辑都不等于审阅答复，真实待定也不因版本承接自动解除。
- 左栏原文保持原样，右栏补改删不反向修改小说、故事或文案。只有用户明确修订原始正文时才更新来源版本与偏移；未说明清楚且影响处理时，只问受影响的具体事项。
- 当前采用稿的文字、声音、人物状态与用户决定是后续依据，不因新版本规则或原文旧措辞擅自恢复已改掉的台词、旁白或其他声音。保存修订依据及新旧稿影响，不把局部改稿当成重写全部内容的授权。
- **定稿后停止主动审改**：按【版本承接】明确采用，或在自主定稿授权内完成，且该范围的必要待定已解除后，只锁定相应稿本与范围。没有新修订授权不再主动润色；用户指定下一步就按本文件交接，未指定才询问。用户新明确全流程委托按总入口【全流程剧本处理】提交本次剧本时，按其要求处理一次并另存新采用版本；这不是准备分镜时主动重审。该全流程的后续阶段、普通继续或中断恢复不重做同一采用稿，后续分镜核对也不变成重写已采用剧本，真实冲突只报告受影响处。
- 修订影响已制作分镜时，只记录稿本变化与影响范围；经统一入口调度时交给 `short-drama-storyboard`，独立使用时将必要影响交接给 `script-to-storyboard`；没有对应重做授权，不自动返工旧镜头，不自行宣布分镜失效、替代提交、扣时或重算视频累计。自主改编授权不自动扩大到既有视频制作。
- 用户“继续”恢复当前已明确的任务阶段；不把无指向的继续当作解除待定、纠错批准或新的全流程授权。按当次实际可读取的当前采用稿和必要承接资料续作，不凭记忆假称已知前文。局部修订不重置其他范围，明确整个项目重置才重置对应记录。

## 交给其他模块时

只交接当前采用且表达落实的剧本及必要版本、范围和状态。正文来自已采用“改后版本”，不另要求用户发送重复 TXT，也不倒回原文或旧声音措辞。自主执行的联合任务，同时交接该采用稿对应的可编辑 HTML 全文对照及实际可用访问方式，最终随提示词交付按[统一交付](../../short-drama-storyboard/references/delivery.md)【自主任务处理后剧本随附】执行；不另造重复副本。

按表达参考【前后剧本的连续承接】保留下一阶段所需承接信息，按【叙事性质与画面承载的正文表达】落实实际事件、回忆、影像、文字等性质与范围。声音、道具和必要承载关系在正文清楚，下游无需猜关键表达。整理标题不自动变成字幕或台词，真实物件文字与声音仍按采用稿用途执行；原文已有摄影指示随相应范围交接，不为交接新造载体、过渡或事件。

来源映射、常规进度、未采用方案和待定解释不作为可执行剧情。真实未决范围不交下游自行补编、删声或决定改法，用户看过草稿不等于批准进入制作。

本模块不自行启动视频制作或场景、人设、道具生成，不擅改已采用的场景资料与视频状态。所选范围按版本承接已采用，或在相应自主授权内完成定稿，且用户已指定分镜时，交接采用稿本及必要版本、范围和状态；经 `short-drama-storyboard` 调度时先交回统一入口，由其按【全流程剧本处理】清点三类资产身份及版本、复用有效资料、补齐授权内所需缺项并检查采用，再调用分镜。独立文本任务已指定分镜时，向 `script-to-storyboard` 交接；用户明确要求场景、人设或道具设定时，向对应独立资产模块交接所需剧本范围与已采用资料，不自行扩成资产生成任务。独立文本交接无需启动总入口流程。接收模块按自身列明的规则及依赖文件执行。不重问已明确方向或重开改编；接收方确有准入问题只暂停受影响范围，不能以场景生成未运行阻止正常文本改编。

独立使用时只完成本次明确委托的文本范围，不因剧本交付而自行启动其他 Skill。经 `short-drama-storyboard` 调度且当前获授权定稿全部正式完成视频提示词、没有其他现成待制剧本时，由统一入口按其自动返回规则恢复文本阶段，不额外询问是否开始续转。本模块收到续转任务后读取当次来源书签、当前采用前稿及剩余正文，从实际断点继续；没有后文才索取，不猜续文。新稿的改编、纠错和审核仍按各自权限执行；自动返回不增加授权，分镜受阻或未完成不视为已耗尽。
