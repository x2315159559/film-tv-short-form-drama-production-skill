# 小说、故事、文案转剧本与剧本整理

本 Skill 独立维护文本改编，不生成镜头提示词，不自行调用分镜或场景生成 Skill。开始转换前依次读取 [表达参考](references/expression-selection.md) 和 [交付参考](references/output-and-state.md)；演绎估时读取[自然演绎估时](../short-drama-storyboard/references/performance-timing.md)。本文件与上述参考定义文本改编；正式交付时同时使用[剧本 HTML 模板](assets/script.html)及[可编辑 HTML 交付](../short-drama-storyboard/references/delivery.md#可编辑-html-交付)，独立导出版随附所需规则与模板，可在新对话或其他 AI 中使用，不以统一入口、其他 Skill、旧聊天、模型记忆、特定目录或专属工具为运行前置。正文、当前采用前稿、必要承接资料和用户决定只取本次实际可读取的内容；缺少必要资料时说明具体缺项，不假称已取得。

## 入口与任务范围

- 统一入口 `short-drama-storyboard` 已登记本次输入的类型时，直接沿用。直接调用时由本 Skill 判断类型并给出简短依据和处理方向，本次授权未覆盖自主判定时，等待用户确认后再处理。同一份已登记类型且未替换内容的续接、表达答复及局部改稿不重复处理类型。新正文或替换正文重新识别。
- 提问、检查、规则修改、场景资料、确认答复和任务续接不当作待改编正文。收到已经是剧本的内容时，说明类型判断。用户已明确委托整理或由统一入口按[总入口](../short-drama-storyboard/SKILL.md)【全流程剧本处理】交来时，类型确定后按本模块处理，不再重问文本还是分镜的方向。任务未明确时，确认是整理剧本还是交接 `script-to-storyboard`，不擅自改编或启动分镜。单独直接分镜不强制进入本模块。
- 转剧本不以独立场景设定、参考图或声音样本为前置条件。按故事核心与表达规则写清剧情所需地点、环境和动作，允许补充合乎情境的普通环境细节；不生成供参考图复用的独立场景设定文档，不自行调用 `short-drama-scene-settings`。已采用且可读取、仍适用的场景资料继续作为剧情约束；缺少独立场景设定本身不算文本表达缺口。
- 只处理已提供或明确委托的原文范围，不猜后文；长篇分批交付完整可追溯单元。正常改编按下文自主完成审阅稿，不逐句审批；表达选择、文本纠错、审阅定稿及旧分镜返工的权限分别按交付参考【本次审核与自主决断】执行。
- 每次续转同一故事，承接当前已采用前稿的剧情状态、人物身份关系、时间场景、道具状态、设定及未完动作或声音；正常换场、跳时和有意断裂依故事需要保留。按表达参考【前后剧本的连续承接】取得必要资料，处理断点与自主授权，不以场景名称一致代替完整续接。
- 只要剧本就按该范围交付；独立使用无需统一入口参与，经 `short-drama-storyboard` 调度时交回稿本、版本和进度。已指定下一步就按交付参考交接，未指定才询问，不自行扩大任务。定稿后停止主动重审、润色，不因准备分镜重开改编；用户新明确全流程委托按总入口【全流程剧本处理】提交本次剧本时，允许处理一次，后续阶段或中断恢复不重复处理同一采用稿。采用、锁定和交接按交付参考【手动编辑、修订与定稿】【交给其他模块时】执行。

## 转换规则

1. **同一故事的核心**：保留主要人物及关键关系、关键动机与选择、核心设定、重要事件与转折、因果链、大纲、主要信息揭示逻辑、发展方向和结局，以及后续依赖的必要信息、伏笔和铺垫；其他会改变故事身份或核心理解的内容也在保护范围内。不能借优化新设重要人物、背景、线索或冲突，不能把推测改成事实，不能把原故事改成另一个故事。
2. **自主改编与人物认知**：在上述边界内，默认可以补充常规动作与表演细节、改写措辞和对白表达；涉及新增或改动未明确状态的情境适配时，先按表达参考【情境变化与状态适配】取得决定。其他表达可调整局部组织与承接，删减重复、冗余及不承担必要剧情信息的内容。原句、原台词和原声音不一律逐字保留；用户指定的用语、原句、专名、语言、发声要求和已确认决定继续遵守。保持关键意思、人物立场、认知和确定程度，不使人物提前知情，不将未读后文可能依赖的信息随意判成冗余。边界不清且可能影响核心时，按表达参考【真实缺口与解除】处理。
3. **表达与声音**：以人物对白和行动推进剧情。按观众此刻应当理解的信息选择人物观察、行动、互动及其他声画表达。旁白与内心独白（心声）并列最低优先级，必要时简短使用；两者合计按表达参考【旁白与内心独白的时长上限】内部核对。声音写清主体、实际内容、方式及先后或延续范围；按表达参考【旁白、心声与画面的配合】完成内容与自然演绎时长的双向匹配，不拖画等声或拖声等画，不计算镜头秒数。
4. **反应与叙事性质**：区分客观发生、怀疑、推测、谎言、梦境、回忆、想象、影像及修辞；比喻不自动变成真实天气或特效。反应须有情境或触发依据，不能改变关键认知与揭示逻辑。展开往事时保持事实时序、必要先后及原有叙事性质，不把所有过去事件都套成人物回忆；常规表演与承接可以补充，不能借此另造重要往事或改变因果。按表达参考【反应触发与回忆入口】执行。
5. **文案与事实**：已有口播、解说可以按同一核心与事实边界整理表达；用户指定的文字与用途按其要求保留。广告、宣传不编造或改变功效、价格、承诺、事实背书或人物经历，缺少必要事实时说明具体问题，不虚构演示或故事填空。
6. **视听落实与文本错误**：正文写清必要场景、人物、动作、道具归属和使用关系、状态变化；情境适配的建议与审批按表达参考【情境变化与状态适配】执行。正文还应落实呈现形式、范围和文字用途；具体按表达参考【通用视听落实检查】【叙事性质与画面承载的正文表达】处理，不能把关键表达留给分镜猜。判断原文本身有错误或冲突时，包括明显笔误，先说明具体原句、问题和推荐处理并询问；只有用户明确授权该类纠错或相关全流程自行决定时，才在范围内直接处理。正常改编自由不等于纠错免问；用户选择逐项处理时一次只问一个独立事项，答后再问下一项。

## 剧本正文边界

正文写实际场景、人物、动作、可表演表现和必要声音。场景标题、动作描述、声音正文与真实入画文字在正文和排版上可区分；标题不自动成为字幕或台词，真实物件文字与声音也不因关键词被删作整理标签。

回忆、梦境、影像等性质、承载关系及范围须在对应正文明确，不用孤立分类标签或空概述代替。具体文字与声音可以在清楚对应的段落间组织，不强制同一自然段，也不要求所有文字一律朗读；用户明确要求的显示与发声关系按其决定执行。参照表达参考【叙事性质与画面承载的正文表达】，不把某作品的载体或某次改法固定为通用机制。

转换阶段不新增景别、机位、摄影角度、运镜、焦点、镜头秒数、切镜或配乐设计；声画承载检查也不扩展为分镜规划。原文已有摄影指示按其位置和作用范围保留，不另加来源或补充标记，不当作新增动作或擅补拍法。原有 Hard Cut、Smash Cut、Jump Cut、黑切等有意断裂依原意保留。

人工后期操作不进入可执行剧本：不新增或执行字幕、字卡、花字、人工调色、合成、后期贴音任务，不建后期备注、A/B/C、人物位置锁定或视频提交标记。摄影表达不因术语而被误判为人工操作；角色台词中的技术用语、物件文字和真实屏幕内容也不能按关键词过滤。

原文混有人工作业要求时，内部保留其原文、范围和技术性质，不交给下游执行；其中承担核心理解或后续情节的必要信息仍须落实为剧情内容。确有无法判断或无法在核心边界内解决的部分，按已有授权处理；未获相应自主授权时说明具体问题并询问，只暂停受影响范围，不另造后期清单兜底。

## 交付与独立维护

与其他阶段联合修订时，实际影响及授权内联动按[内容变更与关联同步](../short-drama-storyboard/references/change-sync.md)执行；只处理可读取的相关成果和已授权范围，不因此启动未委托阶段。文本改编、原文对照及独立执行边界保持本文件原规定。

交付一份可编辑 HTML，正文为“原版／改后版本”两列全文对照并保留未改部分。左栏原文逐字保留，右栏按本模块改编并可直接编辑。按交付参考【单份可编辑对照稿】、表达参考【交付前核对】以及[统一交付](../short-drama-storyboard/references/delivery.md)【可编辑 HTML 交付】落实正文完整性和交付界面。

来源、版本、用户手改最新版、完成状态和中断恢复按交付参考【内部来源与进度】【手动编辑、修订与定稿】维护；按该参考【交给其他模块时】只向下游交接已采用且表达落实的范围、接受自动续转，不猜后文，不把“继续”当作解除真实待定。本模块不擅改已采用的场景资料，也不修改分镜的镜头时长、人物位置锁定和视频进度。
