## 同对话分批续接规则

**【规则定位】**：新对话独立加载；新项目依据当次实际资料从首次处理与空制作状态开始。用户明确续做旧项目时，仅依据本次实际提供、可读取的剧本/已交付提示词、有效场景、必要状态及进度资料恢复，不假定能读取其他对话、其他AI的私有记忆、未提供的外部项目文件或隐含历史。不同AI不会自动共享隐藏A/B/C。本对话内沿用可读原文、资料库、有效权威版本及可读取的正式制作状态，不要求用户重发已有资料；没有可读取记录时按下文核实恢复，不虚构历史。内部记录按下文保存，不强制向用户额外交付来源映射、书签、隐藏状态、状态包或历史复制包，也不把能否提供整包内部记录当作独立运行的前提。

**【内部正式状态与对外交付分离】**：有可读取记录时就使用；仅在当前环境实际支持、后续能够读取的状态载体中保存结构化事实记录。没有记录或记录无法读取时，根据当前实际可读取的原文、设定和已交付提示词核实恢复。无法确定且制作确实依赖的具体信息，按总入口【全流程自主委托】及当前授权处理；确实无法补足时说明缺项及受影响范围，只暂停依赖这些信息的部分，不假称已经保存或记得。记录内容包括：A计划及核验结果、完整身份及形态键、对外显示名映射、B接缝/线程、C热状态、未完声音、来源定位与版本、进度、计时及场景资料库。它们是制作事实记录，不要求保存或展示内部推理过程。制作侧A/B/C全部内部执行，不向用户展示；对外交付的资产交付、完整提示词及总入口组合的同任务已生成场景条目按output-format.md，对外人物位置锁定的输出条件、对应镜号和职责按Workflow §3执行。内部记录无须复制进交付文字才获得保存资格，但分镜状态仍须与已实际交付、可打开的对应HTML内完整段落及结束标记共同正式生效。计划先存为未提交，残段不冒充历史；不能为隐藏制作侧控制而丢掉内部连续性、队列或计时。

**【资产资料库与版本范围】**：人物、场景、道具分别保存实体身份、名称/别名映射、资料来源、可确定事实、覆盖版本和用途、有效与被替代版本。可靠匹配用户已提供资产后登记并复用，不重复生成。身份、用户确认、生成授权、完整成稿、内部检查、登记采用、对外交付和镜头提交分别记录，不互相冒充。人物名称及所需版本足够支持引用时不要求完整外观或图片，场景仍须具备当前摄影必需的固定事实。名称足够引用不登记为“用户已提供资产”；总入口按【全流程自主委托】或逐项授权交接的所需缺失资产任务仍须完成、检查并登记采用，不因可直接引用或不需外发而消失。
   
   独立资产Skill在明确授权范围内完整编写、检查并登记采用的成稿，可作为采用范围的有效资料；外发按[统一交付规则](../../short-drama-storyboard/references/delivery.md)。登记采用不等于已外发：本批只用一段的成稿可保持“已采用、未交付”，支持对应正式镜头；以后满足多次或必要配套附送条件且未发时，按统一交付规则首次发送。未完成、未检查或有真实未决依赖的草稿不能借此绕过缺项。未用成稿完整保存正文、授权、编号名称、版本、检查、采用和交付状态，不声称已发。资料登记或采用不推进分镜书签和视频计时。
   
   新资料替代现行资产并影响旧镜头时，按[内容变更与关联同步](../../short-drama-storyboard/references/change-sync.md)核对差异、实际受影响范围与本次授权，并依该主定义决定直接同步，或说明差异、范围和建议待用户决定；未获旧稿返工或用户资产修改授权时保留旧交付。跨对话或其他AI仅读取实际带入的资产、成稿与明确决定，不假定共享私有资料，缺必要事实才点名索取。分镜模块不生成资产，也不扩大独立资产Skill的生成授权。

**【本批容量选择与恢复】**：输出版本确定、授权默认双版及各版L以[分镜交付准入](admission.md)【本次时长选择】为唯一主定义。内部记录本次制作批次号、明确指定或自主委托来源、适用稿本/范围、输出版本和完成状态；每版分别保存L、计划N段、A/B/C、来源书签、已提交段及有效累计估时，互不覆盖、不把备选版相加。各正式段保留实际采用的L，和实际时长分别记载。尚未完成的同一批按可读安排恢复，不因通用规则更新自动增加版本；新批或明确重生成时重新依主定义核对当前指定与仍有效的自主委托，不因同一项目、输入批次号或“继续”推定旧参数。版本安排可以先于制作存在，但不推进正式书签或计时；没有可读安排且依主定义仍须用户选择时先询问，不从历史实际时长猜测。新选择只作用于其明确范围，旧交付的原容量、编号和有效性保留；返工按2-B及2-C，连续长镜另按Workflow §3。

**【多版本后续采用】**：用户明确要求多版，或依admission.md【本次时长选择】成立自主委托下的双版默认时，正常完整交付对应版本。后续可继续制作双版时，在有效授权范围内按各自书签分别续作，不为此要求先择单。后续工作确实必须只采用一版时，沿用用户已指定的有效版本。尚未指定时，按[总入口](../../short-drama-storyboard/SKILL.md)【全流程自主委托】及有效单项授权确定由谁选择，由AI选择时按本次目标和实际容量登记采用版，由用户选择时再询问。尚未需要选定单一采用版时，不为此阻止多版交付。

各容量版的应发资产集合与本轮实际交付状态分别记录，按[统一交付规则](../../short-drama-storyboard/references/delivery.md)【同轮双版新资产交付】执行。每版位置图另按有效图版本、适用段落及镜号记录待交与已交，绑定对应容量版视频和实际可打开的资产HTML，不以一版已发送或一版视频已完成冒充另一份交付完成。

**【要求变更与估时记录】**：保存可核实的明确反馈、最终决定、替代关系、生效范围和未决事项，区分助手建议与用户已确认要求；短答只指向当时事项。规则记录与当前获授权制作按用户任务并行处理，暂停指示优先，要求记录不自动授权修改Skill。无法核实且确有必要的具体沟通记录缺口按总入口【全流程自主委托】及当前授权处理，不伪造逐字对话、确认或内部思考。本规则文件自身即为通用执行依据，不要求查其他聊天。时长只按文字、情绪、停顿和声画双向承载估算，登记为估时，不声称已获得配音或成片实测；不设置音频采集、真人试读或语音校准流程。新节奏规则只用于其生效后的新制作，不自动返工已交付段落。

提示词、资产、规则及其他采用内容的修改，统一按[内容变更与关联同步](../../short-drama-storyboard/references/change-sync.md)检查实际影响，并在既有授权内同步相关版本、状态与交付记录；未受影响且仍有效的检查结果继续复用。

1. **【当前对话已生效历史】**：仅含按铁律0已提交的内部B接缝/线程和C状态（含隐藏但仍有效的事实、来源书签和计时）、可见人物锁定、完整段落时长，以及已成立的场景资料/版本与用户明确修订。未提交计划不得作为制作历史跨回复恢复；可读完整资产成稿可依【资产资料库与版本范围】作为资料恢复，不据此恢复未提交分镜事实；已采用资产与未提交镜头计划分别判断；不能因为正式内部状态不向用户展示就拒绝读取实际可用的记录；记录无法读取时按【内部正式状态与对外交付分离】依据实际可读资料核实恢复，不假定已交付提示词包含全部隐藏状态，也不以补发A/B/C为固定要求。

2. **【当前待处理剧本范围】**：只处理已登记输入队列、尚未完成且未被用户明确跳过的可读采用剧本。用户直接提供并采用的剧本、文本模块交接且已正式采用或在明确授权内已自主定稿的右栏剧本，都可直接登记，不要求用户重新上传已可读的定稿。按有效输入的进入顺序追加新后续剧本；明确替换/修订既有剧本按2-B处理，不重复追加旧内容；有旧稿剩余时先处理旧稿，再进入新稿，除非用户明确要求跳过或舍弃。用户回复“继续”或插入讨论后恢复时，从最后已生效制作进度书签继续，不把紧邻的上一条消息机械当作剧本。未经用户明确要求，不重新处理已完成范围；不得自行调用未登记旧稿或猜测后文。

2-A. **【输入队列与制作进度书签】**：每批有效剧本按进入顺序赋稳定输入批次号和初始稿本版本；用户直接提供时绑定来源消息或附件，文本转剧本时绑定能够读取的正式已采用或自主定稿右栏及其交接信息。小说原文、左栏及其他来源只留作溯源，分镜书签逐段定位实际采用的剧本。一次输入含多份剧本时另加稿件序号，修订版保留输入身份并按2-B递增稿本版本。输入批次号与视频段落号分开，重复台词不合并。输入队列依据有效采用稿及用户明确的跳过/修订指令确定，不因输出中断丢失；登记输入不代表已制作完成。

每段内部C记录本段处理的采用剧本范围及下一未处理位置，定位采用“输入批次号＋稿件序号（如有）＋稿本版本＋采用剧本自然段序号＋段内字符边界”（从1计，含标点，段号在对应版本内固定），辅以剧本短句锚点；跨输入批次时分别列出。台词截断时逐字保存采用剧本该句的未处理文字；动作跨段未完成时，同时记录剧本位置及已完成/待完成阶段，不因引用过语句就认定动作完成。记录尚待处理的输入批次及顺序，不复制整批剧本。

以实际交付且可打开的对应视频HTML中完整段落及【段落结束｜{编号}】按铁律0推进；草稿、残段和未交付文件不推进。用户修订引起的定位迁移按2-B处理，不算新增完成进度。中断后从最后已生效书签恢复，尚无正式段落则从队首起点开始。旧历史无书签时，用最后正式完整交付内容与相应采用剧本匹配补建。无法唯一定位时只报告具体缺项并按本次授权处理，不猜测或跳过未完成内容。书签及来源映射只内部保存。

2-B. **【剧本修订与进度迁移】**：用户明确替换/纠正已有剧本时，登记同一输入的新稿本版本、替换范围及版本对应关系，保留旧版本供核对，不将替换内容当后续新稿追加。先按明确替换范围、采用剧本锚点及上下文核对已完成范围、未完台词/动作与下一位置，再生成新版定位；禁止直接套用旧版字符偏移。只有未处理内容变化时，保留此前完成进度，将未处理范围映射到新版；已完成内容也变化时，列出直接受影响的已交付段落及依赖其事实的后续状态/接缝，标明需重做范围，无关段落、资产与编号保留。用户已明确要求重做时，从最近仍有效的状态处理新版受影响范围，新交付段号继续顺延，C记录来源版本、替代旧段号及覆盖范围；替代以完整旧段为单位，重拆范围须保留其中仍有效的未改内容，不能只输出改动句就认定整段已重做；旧交付记录保留，但被明确修订否定的状态不得继续用于新版，重做的未完成部分仍留队列，不因已有旧交付而跳过。未明确返工范围时依【全流程自主委托】及关联同步主定义处理；仅暂停依赖失效状态的续接。无法唯一确定修订对象、版本对应或接续位置时，按当前授权处理缺项，不猜测、跳过或默默回滚全项目。版本登记与定位迁移由用户明确修订生效，即使尚无新段提交也保留；它们不表示改稿已经制作完成，新输出仍按铁律0逐段提交。

2-C. **【项目交付计时】**：累计口径为当前项目已正式交付且仍有效的段落总时长，不是本轮回复时长，也不是剧情世界时间。每段C记录本段时长、本次计时增减及提交后的项目累计秒数，依铁律0仅在本段所在的完整HTML实际交付且可打开、结束标记完整时计入一次。同一段重显、未提交计划和中断残段不重复计入；分批发送、“继续”及跳过尚未制作内容不清零。明确修订使旧交付退出当前有效版本时，在修订记录登记应扣旧段号/时长；读取累计时先应用尚未计入C的已生效修订调整，后续正式提交的C保存调整结果；新交付逐段加计，替代关系中的旧段只能扣除一次，未完成重做不得假称全部完成。项目级重置才从零开始。旧历史缺少计时记录时，可依据本对话完整交付段落的时长及明确替代关系重建；信息不足则说明累计暂不可核实，不编数字，其他可确定的制作内容可继续。

3. **【同对话新批次自动续接】**：新发送的后续剧本默认是同项目下一批；按输入队列及最后已生效书签继续，并自动读取【当前对话已生效历史】。除非明确【项目级重置】，不得当首次处理；只点名资产重置则仅按3-A处理。

4. **【分批发送不要求预知后文】**：只处理【当前待处理剧本范围】；未提供后文不得猜测、预建无调用资产或虚构状态。仍有可处理剧本剩余才提示继续；视频和对应应发资产、位置图都正式完成后报告准确完成范围。由统一入口调度时交还状态，按[输入路由](../../short-drama-storyboard/references/input-routing.md)的主定义衔接；独立使用本Skill时只交成果及实际缺项，不自行启动其他Skill。场景缺项、修订未决或残段不算全部完成，不因受阻跳过队列；由入口继续工作时，按总入口【全流程自主委托】及当前授权处理实际缺项。

5. **【同对话异常中断恢复】**：按铁律0及[可编辑 HTML 交付](../../short-drama-storyboard/references/delivery.md)恢复。每版核对已实际交付、可打开的HTML和其中完整段落的结束标记，据最近生效书签、未完台词/动作继续，保留已生效段落、有效资产及原版本范围。分次交付时，同一版每次交的文件均完整可编辑，原编号顺延，续发相应未完成范围；仅对明确需要修订的已交范围按2-B/3-A及关联同步处理。

   每版另外检查对应资产HTML及位置图待交清单。已完成的视频段不因配套资产文件待交而重发；位置图尚欠时在该版资产HTML仅补发欠交位置图，保存原适用段号、镜号及已生效交付。位置图状态变更不推进视频书签或计时。资产是否应发及其状态按各自规则核对，不将尚待交的条目登记为已外发。

6. **【线程与权威场景设定续接边界】**：正式历史与线程恢复只读可恢复的正式事实和当前有效场景版本；完整资产成稿按【资产资料库与版本范围】恢复其已登记采用范围、有效版本与实际外发状态，不把未外发误判为未采用，也不据此将未提交分镜计划恢复为正式历史；不凭相似剧情或同名场景脑补；内部历史不可读时按【内部正式状态与对外交付分离】恢复。无关隐藏角色位置、衣内持物及完整形态仍内部保存，不抄进用户可见字段；已确定且为当前画面必要的佩戴、持有或遮挡关系按core-rules.md铁律8-C写清，本体全遮不列实际入画道具，异地现实身体不外写。资产及后到资料按3-A和场景主定义，剧本版本与已获决定的返工范围按2-B。新用户场景尚待处理决定时，旧交付记录保留，不将来源优先误作已批准全量返工。

7. **【编号连续】**：同一项目在本对话内续接，或依据本次提供、可读取的有效资料跨对话恢复进度时，段落编号、已注册实体名称、形态、时空线程键、场景资产单元名称、连接结构语义名称与其他全局唯一标识均跨用户消息连续顺延，不因用户分批发送剧本而重置。
